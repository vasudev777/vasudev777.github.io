Research-Backed Architecture · IJARESM Published

Shram

Lead Developer & Researcher: Vasudev Parmar · Paper: Shram: A Practical Approach (ISSN: 2455-6211)

Verified Production Stack

PHP (Core SSR) MySQL Prepared Statements Razorpay Payment Gateway Dompdf Invoicing PHPMailer (SMTP) Firebase Google Auth Bcrypt Hashing .htaccess Server Rules Android APK Wrapper

1. Executive Summary

Shram is a full-stack digital hiring and procurement platform designed to address critical inefficiencies in India's unorganized construction sector. Backed by my research paper published in the International Journal of All Research Education & Scientific Methods (IJARESM), the platform eliminates intermediary brokers by enabling direct hiring for 7 specialized labor crafts, contractor allocation, and an integrated construction supplies e-store with secure digital payment processing and automated invoice generation.

2. Problem Statement & Ground Reality

🏗️ 40M Unorganized Workforce

According to Ministry of Labour data cited in the research, over 40 million individuals are employed in construction with high underemployment and irregular work access.

💸 20%–30% Brokerage Cuts

Informal artisans gather at morning labor hubs (naka / chowk) and rely on middlemen (thekedaars) who extract up to 30% of their daily earnings.

🔍 Hiring Disconnect

Homeowners and builders face communication gaps and delays when sourcing dependable workers for household tasks or project contracts.

🛒 Procurement Fragmentation

Sourcing plumbing, electrical, and hardware supplies requires separate offline trips, causing avoidable project downtime.

4. Technical Implementation & Security

Dual Authentication & Credential Security

Incorporated Firebase Google Sign-In for frictionless client onboarding alongside Email OTP verification powered by PHPMailer with authenticated SMTP. Passwords stored with one-way Bcrypt hashing.

Defensive Engineering & Defensive SQL

Zero raw query concatenation; all database operations strictly leverage MySQL prepared statements to prevent SQL injection. Server-level protection configured via .htaccess rules (disabling direct directory traversal and protecting sensitive files).

Payments & Automated Invoicing Pipeline

Integrated Razorpay Payment Gateway for advance bookings and material checkout. Paired with Dompdf to dynamically render and download itemized purchase bills, tax receipts, and work order slips as standardized PDFs.

Explore India is an end-to-end travel technology platform engineered to eliminate travel fragmentation in India's tourism ecosystem. The platform unifies tri-modal transport booking (flights with an interactive graphical 2D seat selector, railways, and distance-based cabs), dual-track itinerary planning (curated regional packages vs. dynamic custom builders), and a vetted local guide marketplace under a single transactional pipeline backed by Razorpay payment processing and automated SMTP booking documentation.

2. Problem Statement & Friction Points

🚆 Disconnected Travel Silos

Planning holidays in India traditionally requires switching between multiple portals for train booking, flights, inter-city cabs, and hotels with no unified booking workflow.

⚖️ Rigid vs. Overwhelming Choices

4. Interactive Graphical Flight Seat Selector

Instead of a generic form dropdown, built a custom interactive visual aircraft cabin map:

2D Airplane Fuselage Map

Rendered with aerodynamic nose/tail vector shapes, emergency exit rows, and a standard 3x3 seating grid (A, B, C | Aisle | D, E, F) accommodating up to 180 individual seats.

Deterministic Seeded Occupancy

Uses cyclic redundancy check hashing on the combined flight number and travel date to seed pseudo-random occupied seat maps. Returning visitors consistently observe the exact same occupied vs. available seat states for any specific scheduled flight.

Real-time Client-Side State Management

Enforces dynamic seat states (🟢 Available, 🔴 Booked, 🔵 Selected), restricts selections to selected passenger limits, and recalculates total fares before passing data to checkout.

5. Inter-City Cab Engine via Haversine Distance

Mathematical Formulation

Applies the Great-Circle Haversine Formula against origin and destination coordinates stored in the relational database ($R = 6371\text{ km}$), estimates driving durations, and dynamically calculates fares across vehicle classes:

Dual-Panel Restaurant Platform · Hospitality & Food Redistribution

Zaika

Lead Architect & Developer: Vasudev Parmar · Digital Restaurant & Surplus Food Redistribution Ecosystem

Verified Production Stack

PHP (Core SSR) MySQL Relational Schema PHPMailer (SMTP Alerts & OTP) Firebase Google Auth Active Session Security Bcrypt Hashing Android APK Distribution

1. Executive Summary

Zaika is a dual-panel (Customer/Admin) digital restaurant and hospitality platform unifying admin-reviewed dine-in reservations, a multi-cuisine ordering and takeaway system with pickup-OTP verification, and an active surplus food donation pipeline connecting the commercial kitchen directly to verified local NGOs for community food redistribution.

2. Problem Statement & Friction Points

🚫 High Table No-Show Rates

Unverified reservations lead to frequent ghost bookings and vacant prime-time seating, causing immediate revenue loss during peak dining hours.

📦 Multi-Channel Friction

Disconnected workflows for dine-in tables, telephone takeaway orders, and order history create preparation delays and customer confusion.

🍲 Commercial Kitchen Food Waste

Restaurants routinely generate surplus edible food with no structured, traceable channel to safely log and redistribute meals to certified charitable organizations.

3. The Dual-Panel Model

👤 Customer Panel

Submit dine-in table requests, order multi-cuisine takeaway meals (secured via pickup OTP), review unified dining history via a dual-toggle view, and submit feedback.

🛡️ Admin Management Panel

Audit dine-in reservations (accept/reject with explicit reasons), manage dynamic menu items, log daily surplus food donations to NGOs, and enforce immediate live session termination.

5. Key Engineering Implementations

Admin-Reviewed Table Reservation Workflow

Customers submit a dine-in booking request that does not auto-confirm. The admin audits the floor plan and either accepts or rejects the request. On rejection, an automated PHPMailer alert is dispatched to the guest detailing the stated reason, eliminating ambiguity around denied bookings.

Takeaway Ordering with Pickup OTP

Structured multi-cuisine catalog with AJAX-driven cart modifications. Upon order placement, a unique pickup OTP is generated; the customer presents this code at counter collection, preventing order handoff mix-ups and unauthorized pickups.

Unified Customer History (Dual-Toggle View)

A consolidated user portal featuring a dual-toggle view that lets guests seamlessly switch between their dine-in reservation logs and takeaway orders in one unified interface rather than fragmented separate history screens.

Immediate Live Session Invalidation on Account Block

Engineered an active session-validity lookup checked on each request header. If an administrator blocks an account, their live session is instantly terminated, eliminating the vulnerability window where a blocked user could continue performing actions on a stale token.

Surplus Food Redistribution & NGO Audit Portal

Enables kitchen staff to log daily surplus prepared food with exact quantities and metrics (KG / Portions). Maintains an active NGO registry with transparent donation histories, creating an auditable track record of food diverted from landfills.

Defensive Security & Authentication Layer

Triple auth supported (Email/Password, Email OTP, Firebase Google Sign-In). All database queries run through MySQL prepared statements, passwords hashed with Bcrypt, and sensitive directories shielded via server-level .htaccess rules.

Kaggle Capstone · AI-Native Prototype · Autonomous Goal Planner

Workspace Concierge

Creator: Vasudev Parmar · Built via AI-Assisted Vibe Coding for Google's Kaggle AI Agents Intensive

Architecture & Methodology

AI-Assisted Vibe Coding Google Gemini API Dual-Agent Specialization MCP Tool Calling Stateful JSON Memory Vanilla Glassmorphic UI Render Cloud Deployment

1. Project Context & AI-Assisted Philosophy

Workspace Concierge was built as a capstone project for the Kaggle 5-Day AI Agents Intensive Course (powered by Google). Rather than hand-writing boilerplate framework code, this prototype was developed entirely using modern AI-assisted vibe coding and prompt engineering. The engineering objective was to design and ship an end-to-end multi-agent system demonstrating three core agentic fundamentals: autonomous task decomposition, tool invocation, and stateful memory persistence.

2. Problem: The "Blank Canvas" Planning Paralysis

🎯 Broad Aspirations vs. Execution

Users frequently set ambitious targets (e.g. "Learn Pandas in 3 days" or "Prepare for System Design") but stall because decomposing them into structured, day-by-day actions creates high cognitive friction.

💬 Stateless Chat Limits

Standard chatbots return long walls of text that quickly scroll out of view, lacking persistent board tracking, dynamic resource injection, and interactive task status updates.

3. Agentic System Architecture & Workflow

Tier 1 • Client Interaction Glassmorphic Frontend
🎯

Goal Input & Interactive Kanban Board

Lightweight Vanilla HTML/CSS/JS dashboard tracking daily milestones (Todo ➔ In Progress ➔ Done)

Agent Prompting & State Request
Tier 2 • Agent Orchestration (Gemini API) Dual-Agent Workflow
🤖 Planner Agent

Deconstructs high-level goals into structured day-by-day milestones using strict schema validation

💬 Coach Agent

Embedded conversational guide reading active board context to answer questions on specific tasks

🛠️ MCP-Style Tools

Functions to load/save workspace state and dynamically inject tutorial/documentation links into tasks

JSON State Read / Write
Tier 3 • Persistent State Memory Session Longevity
💾

State Store (`workspace_state.json`)

Persists task completion, card status transitions, and agent conversation threads across restarts without heavy database overhead.

4. Key Agentic Concepts Demonstrated

Dual-Agent Specialization

Separates the strategic planning phase from real-time coaching. The Planner Agent focuses purely on hierarchical goal decomposition, while the Coach Agent handles reactive conversational guidance in the context of the user's active board.

MCP-Style Tool Invocation

Equipped with specialized callable skills: reading current state, persisting card modifications, and automatically querying dynamic learning resources to attach relevant video/article references to each task card.

Prompt Engineering & Structured JSON Output

Constrained LLM responses to strict JSON schemas, ensuring that generated multi-day roadmaps parse reliably and render instantly on the interactive Kanban board without malformed UI errors.

AI-Native Engineering Insight

What This Project Demonstrates in Practice

This capstone demonstrates how modern AI pair-programming and vibe coding can be harnessed to design, orchestrate, and ship functional agentic applications rapidly. Rather than getting bogged down in boilerplate framework setup, the focus was kept on agent prompt architecture, state management, and real-world deployment on Render.
